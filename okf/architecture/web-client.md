# Structure

A static, build-free client in `web/`: `index.html`, one stylesheet (`css/app.css`) and ES modules. Every library is vendored in `web/vendor/` at an exact version and loaded locally, so the client renders with no internet ([vendored web libraries](/environment.md#vendored-web-libraries)): GridStack (panel grid), MapLibre GL (2D map), ECharts (charts), globe.gl (Cinema globe and Threat Origins 3D; echarts-gl was removed, because it needs eval, which the [Content-Security-Policy](/architecture/deployment.md#content-security-policy) refuses) with NASA's public-domain globe images (`vendor/nasa/`), Cytoscape (entity graph, loaded on demand, no CDN fallback), the Inter, JetBrains Mono and Fraunces fonts (`vendor/fonts/fonts.css`), and the map glyphs. All URLs are page-relative, so the client works at `/` (how Caddy serves it) or behind a prefix of your own proxy, such as `/cyberintel/`.

# Panel contract

A panel module calls `registerPanel` at import time:

```js
registerPanel({
  id: 'world-map', title: 'World Map', description: 'one line for the widget menu',
  w: 8, h: 8, minW: 3, minH: 3,          // grid units: 12 columns, 62px rows
  mount(body, ctx) { /* ... */ return { destroy, resize, refresh }; },
});
```

`ctx` gives the panel:

| Member | Purpose |
|---|---|
| `api`, `live`, `store`, `util` | Shared modules. |
| `openEvent(id, {opener})` | Open the shared event drawer, the side panel for events ([opening things](#opening-things); `opener` overrides where focus returns on close) (`aria-hidden` and `inert` only while it is closed, so screen readers read it when open and Tab never lands in it off-screen). It is `role="dialog"` labelled by the event's title (`#drawer-title`), not modal, so focus is not trapped (no `aria-modal`): opening moves focus to the drawer (an amber focus ring; Tab continues into it), and closing (Esc or the close button, labelled "Close event details") returns focus to what opened it: the focused control, or the row that was clicked (a plain feed row gets `tabindex="-1"` so focus can land on it), else the same row by event id, else the active view tab. An event opened from inside the drawer keeps that opener. The body leads with plain words: the source's name as Settings › Sources shows it, severity as a word with its score ("High (80 out of 100)"); the source id, event id, coordinates and raw file sit under a collapsed **Technical details**. For an event with an IP, **Listed by N feeds** lists every feed that listed the address and when it last did (`reported_by`), with a line saying this is corroboration, not a confidence score, since some feeds copy each other ([counting addresses](/architecture/api.md#counting-addresses)). Event fields are untrusted feed/upload data: every key/value is escaped; only markup the drawer builds itself, wrapped as `trusted(html)` (the Raw file span under Technical details), is rendered as HTML. A feed-supplied `url` becomes a link only if `util.safeUrl()` accepts it (http/https, or a path written as one: `/x`, `./x`, `../x`; a bare word or sentence is text, not a same-origin link); `javascript:`, `data:`, `vbscript:` and anything else is shown as text. The same check guards every feed URL rendered as a link or image (entity panel citations, feed panels and Bluesky avatars, Cinema, Network source homepages, News story/article "Original" links, the entity page's reference, evidence and references links, Sources homepages); an unsafe URL renders as plain text or the link is left out, and nothing is opened. |
| `setBadge(text, isLive)` | Chip after the title (a count, or LIVE). |
| `setUpdated(time)` | "3m ago" freshness label; ticks automatically. Its hover title spells it out: "Updated 3m ago (22 Nov 02:37 EST): when this widget's newest data arrived" for a data time, "Refreshed 4s ago (…): when this widget last checked for new data" for a redraw time, and the panel title carries the same text, so it is still there when a narrow header drops the label. |
| `tools` | Header element for extra header widgets (today the Exploited Vulns sparkline). It clips as the header narrows and hides when the header is under 300 px wide, so put nothing there that is the only way to reach a feature. |
| `panelEl` | The panel's root element. |
| `state.get()`, `state.set(patch)` | Per-instance UI state persisted in localStorage. |

Panel headers fit any panel width: the Expand and Remove buttons always stay inside the header, the title and badge ellipsize, and as the header narrows the freshness label, then `tools`, then the badge drop out (container queries on `.panel-head` in `app.css`); the title's hover text keeps the freshness.

The shell calls `resize()` whenever the panel's box changes and `refresh()` when the global range or search changes. Panels must not initialise charts or maps until their body has a non-zero size (use a ResizeObserver); the shell skips resizes while the Ops view is hidden and mounts the deck lazily on first visit.

# View contract

`registerView({ id, mount(el, ctx), show(), hide() })` for full-page views. `mount` runs once, on first visit; `hide` must stop animation loops and timers, `show` restarts them. The navigation shows `watch`, `network`, `news`, `entities` (labelled Intel), `ops` and `cinema`, in that order; `explorer` (the SQL console) and `settings` are views without a tab, opened from the gear menu, ⌘K and links (the shell accepts any id in `VIEWS` from the URL hash), and the current view is kept in the URL hash. A tab click adds a history entry (opening or closing a News story does too), so browser Back and Forward step between views; a view reached by a hash change (a link, Back/Forward) leaves history alone, and boot only rewrites the current entry. A hash change to `#<view>` or `#<view>/<sub-route>` from anywhere switches view, and the shell leaves the sub-route in place for the view to read: `#network/<tab>` (overview, alerts, hunt, devices, import), `#news/story/<id>`, `#news/article/<id>` and `#entities/...` all work as links. A view adds its tab with one `<button data-view>` (in `.views`, and in `.bnav` if it belongs in the phone bar) and one `<section class="view">` in `index.html` and one line in `main.js`.

**Old routes and aliases.** `#intel[/…]` is rewritten to `#entities[/…]` and `#sources` to `#settings/sources` before any view's own `hashchange` listener sees them (the shell registers its alias listener when `shell.js` loads, rewrites with `replaceState` and re-dispatches `hashchange`), so old links and bookmarks land on the new home with no extra history entry. `#explorer`, `#ops`, `#cinema`, `#network/…`, `#news/…` and `#entities/…` are unchanged. `#explorer/find?q=<text>&country=<CC>` (the Network pivots' "Find in the SQL console") opens the SQL console on the matching events. With no view in the hash, Night Desk opens on the landing page from Settings › Display (Watch by default).

# Decks and layout

Decks are named layouts of `[panelId, x, y, w, h]`. Four templates ship in `shell.js` (v1.1: the Feed Health panel and Threat Origins 3D are no longer in any template but stay in the **+ Widget** catalogue; a saved copy of the old Cyber Ops (v1.0, or v1.0 plus the network widgets) or Threat Infrastructure template that still equals it exactly, every panel at the same position and size, is dropped once (`nd.decks.v11`) so it follows the new template; a layout where anything was moved, resized, added or removed is kept); changes are saved per deck in localStorage and custom decks can be saved under a new name (not a template name; blank names are ignored). Names compare case-insensitively: `cyber ops` is refused as the `Cyber Ops` template, and saving as `mine` when `Mine` exists updates `Mine` rather than adding a second deck. Reset returns a template to its shipped layout and a custom deck to the layout it was saved with (`nd.deckBase.<name>`); custom decks saved before that existed offer no Reset. Below 760px the grid becomes one column, and that phone stack is never saved over the desktop layout. On a phone it is also read-only (`syncPhoneDeck()` in `shell.js`): no drag handles and no close buttons, and your own network first (Needs attention, Newly exploited, Devices, Network timeline, then the rest in reading order). **Edit layout** in the sub-bar (phones only; ⌘K "Edit the Ops layout") brings the handles and close buttons back until **Done**.

# Global state

`store` holds `{hours, opsQ}` (the Ops deck's range, remembered in localStorage `nd.range` and written to `#ops?range=`): the time range and the Ops deck's text filter (set only by the explicit "Filter panels" row of the global search; other views keep their own queries). `store.sinceHours()` gives the API `since_hours` value (undefined means all time). Panels either implement `refresh()` or subscribe to the store directly.

# Network view

`js/views/network.js` registers the `network` view over [network logs](/data/netlog.md). It hides the global sub-bar (`body.nv-active`) and has its own header: five sub-tabs (the URL follows the active one as `#network/<tab>`, so reload, Back/Forward and shared links return to it) and the shared [time range](#time-ranges) (24H, 7D, 30D, ALL, or a window set by dragging across any timeline, shown in the control as "Nov 3 – Nov 5 ×"; it is hidden on Devices and Connect logs, where it does nothing). Sub-tabs mount lazily and share state in `net/common.js`: `S.range`, the hunt filters `S.filters` (`{f, v, neg}`, serialised by `huntQuery()` into the backend's `query` grammar), `S.groupby`, and caches of devices and sources. Modules talk through `onChange`/`emit` with the topics `range`, `filters`, `data` and `alerts`; the live topic `netlog_alerts` triggers `data`. The header line reads "rows · devices · files · alerts · N new" with the words of [which number](/data/netlog.md#which-number); the Alerts tab number is the "new" count in the current range (`GET /incidents/summary` with the range, the list's "New" chip), the Devices tab every device. **A failed load is an error, never "no logs"**: when `GET /summary` fails (`S.summaryErr`), the header says "Couldn't reach the Night Desk server · trying again" and Overview shows "Couldn't load your network logs" with Try again and the server's message under Details. The summary is read again every 8 s while the view is open, when the live stream reconnects and when the view is shown; on success Overview, the device cache and the panes reload by themselves. **Overview** is one grid: the needs-you card with the chart right under it on the left, "Are my logs current?" and Active devices on the right; the chart takes the height the right column leaves (one column below 1100 px: card, logs and devices, chart). On All, the chart starts at the [chart start](/data/netlog.md#chart-start).

# Watch view
`web/js/views/watch.js`, the default landing view (`#watch`, the first tab; boot falls back to it with no hash). It
renders `GET /api/watch` (sections in a fixed order: Your network, Touches you, Newly exploited, News you follow, Big
stories, Feed health only when something is wrong) as one column, with the setup checklist (`GET /api/setup/status`) on
top on a new lake. **Caught up** moves the one app-wide marker (`PUT /api/marker`) that News and the Ops KEV panel also
read; News "Mark all as read" is the same action. Rows are links (`#network/alerts/<id>`, `#news/story/<id>`,
`#sources`) or open the KEV event drawer. Live topics: `netlog_alerts`, `events` (cisa_kev), `marker`. The sub-bar is
hidden on Watch. Full contract: [Watch](/architecture/watch.md).

A dotted quad written after "version", "release", "build" or "patch" is flagged `version?` in IoC tables and left out of STIX (it stays in CSV and MISP with `to_ids: false`).

# Entity panel

`js/core/entity-panel.js` is a shared right-hand drawer for any entity, reusable by every view: `openEntity(id, {actions, onArticle, source})` or `window.ndOpenEntity(id, opts)` (views normally go through [`core/open.js`](#opening-things)). From `/api/entities/<id>` it shows the type, name, aliases, description, mentions, sources, claims, first and last seen, a mention-trend bar chart, a **brief** of the strongest reported claims with their quotes and numbered source citations, a key indicators table (from claims and co-mentions), related entities by type, sources, and an **Open full page** link to `#entities/<id>` in its header. The shared [assessment](#assessment) comes first; CVEs add ransomware use, CWE and affected products below it. `actions` adds view-specific buttons (the News view adds Follow and Filter stories), and `onArticle` lets a citation open an article in place. Without the entities layer it shows the id and says the details are unavailable. Opening it moves keyboard focus into it; closing (Esc, ×, the scrim) returns focus to what opened it, or, when a live panel re-rendered that chip meanwhile, to the chip with the same `data-entity` in the same Ops panel or view. CVEs show CISA's required action in its own full-width row of the facts box (never inside the narrow vendor cell); counts read in the singular for one ("1 claim"), and "first in your data" appears once (the tile; its tooltip holds the date). Switching view closes it (and its scrim). CSS prefix `.ep-`.

The News view adds an **executive brief** to the panel, in its own functions at the end of `entity-panel.js`. It draws on [`/api/news/entity-brief/<id>`](/architecture/api.md#news) (`osinthub/news/brief.py`):

* **Why this matters now:** the latest report, 30-day versus previous-30-day mentions, and what the entity exploits, targets and uses, each with numbered citations.
* **What to do:**
  * For actors and malware: CVEs to patch (KEV first), MITRE mitigations mapped from the ATT&CK techniques in its reporting via the bundle in `ref/`, and indicators to block.
  * For CVEs: KEV and exploitation status, who exploits it, and the affected products to check.
* **Local-LLM wording:** generated in the background and cached in `settings` under `news.entity_brief.<id>`. It is keyed by a hash of the entity's claims, so it refreshes when they change. Until then the deterministic facts are shown. The section header says where the wording comes from (`llm_status`): "local LLM" (with "refreshing" while stale), "facts from the lake · AI summary pending", or, when the AI helper is down (`llm_unavailable`), "facts from the lake · AI wording unavailable" (or "older wording, AI helper unavailable" over cached wording), with a tooltip explaining it; no retry is scheduled in that case.
* **Alias table:** each alias with who lists it (MITRE ATT&CK, the MISP galaxies) and its naming scheme (Microsoft, CrowdStrike, Mandiant, Proofpoint, Unit 42, CERT-UA).
* **Mention trend:** 12 months of weekly mentions across articles and events. When the data is sparse it shows "N mentions since <date>" instead of an empty chart.
* **Claim confidence:** the stored score plus its basis (origin, distinct sources, tiers), labelled single source, two sources or corroborated.

The drawer opens over a scrim and never reflows the view underneath.

**Hover cards** (`[data-entity]` chips, pointer devices only, `role="tooltip"`) are dismissible (WCAG 1.4.13): Esc hides a shown card without moving the pointer or focus, a press anywhere outside it hides it, and the chip a panel was opened from (or whose card Esc dismissed) shows no card again until the pointer has left it, so closing the panel never pops the card back under a resting pointer.

## Opening things

One grammar for every entity reference in the app (`js/core/open.js`, v1.1; it replaced two opposite grammars and six labels):

| Gesture | Opens | Label |
|---|---|---|
| Click (or Enter on a focused link) | The side panel: the entity panel, or the event drawer for events | **Details** |
| Cmd-, Ctrl- or Shift-click, middle click | The full page `#entities/<id>` in a new tab | **Open full page** |

* **Real links.** Chips (`a.vx-chip`), Intel chips and rows, News chips and highlighted names (`a.nw-chip`, `a.nw-hl`), Network values that name an entity (`a.nv-v`, whose click stays the pivot menu), the event drawer's CVE ids and linked entities, the panel's related chips and indicator rows, graph links and the Watch KEV rows are `<a href="#entities/<id>">`, so the browser opens a new tab natively, and right-click or long-press offers "Open in new tab". For references that are not links (`[data-entity]`, News' `[data-eid]` buttons, `[data-ep]`), `open.js` handles Cmd/Ctrl/Shift-click in the capture phase and middle click on `auxclick`, opening the full page with `window.open(href, '_blank', 'noopener')`; the row, pivot menu or panel under it never sees the click.
* **The two labels.** Only **Details** and **Open full page** name these actions: the panel header and footer, the hover card, the Network pivot menu, the graph side panel and the entity page's compare columns. The panel shows **Open full page** once, in its header. A plain click on an **Open full page** link (`[data-open-full]`, also the Review queue's "open the full page of …" hints) closes the panel and navigates in this tab.
* **API:** `LABELS` (`details`, `full`), `entityHref(id)`, `newTab(event)`, `openDetails(id, event?, opts?)` (panel, or new tab when the event asks; returns `'panel'` or `'tab'`), `openFull(href, event?)` (new tab, or this tab with the panel closed) and `fullLink(id, cls?)`. Global search uses `openDetails` for entities and CVEs and `openFull` for articles. The Network pivot menu stays the click on `.nv-v` values; its **Details** and **Open full page** items go through the same helpers.
* **One side panel at a time.** The event drawer (`shell.js`) registers as the entity panel's event host (`setEventHost`). An entity opened from inside the event drawer replaces it: the drawer closes and the panel opens with a **Back** control ("Back to the event: …"); Back reopens that event, and links followed inside the panel stack up and step back the same way. An entity opened from anywhere else closes the drawer without a Back step, and an event opened while the panel is up replaces the panel. The swap skips the slide so the two never cross. Esc closes the whole panel; Backspace (outside a text field) steps back. Focus moves into the panel on open and returns to what first opened the event or entity on close (the same row by event id, else the active view tab, which is the bottom bar's on phones).
* **Phones (≤ 760 px):** the entity panel and the event drawer are full-height sheets over the top bar and the bottom bar.
* **History.** Panel state is not in the URL (it never was); a full page is a normal `#entities/<id>` entry, so browser Back and Forward and deep links work as before, and the Intel view closes the panel on its own route changes.

## Times and dates

One helper, `js/core/time.js`, formats every time a person reads, so the same moment reads the same on Watch, Network, News, Intel, Help, notes, Ops panels, Cinema and the top bar. One setting, Settings › Display › **Show times in** (localStorage `nd.timezone`): **local time** (the default, the browser's zone) or **UTC**. Always 24-hour; one date style ("7 Nov", "7 Nov 2025" in another year); one "ago" rounding (whole units rounded down: "59s ago", "5h ago", "3d ago"; durations such as "no new records for 3 days" round the same way). Changing the setting reloads the page once so every view redraws. The top-bar clock follows it and names the zone ("23:34:13 EST", "04:34:13 UTC"); clicking it opens Settings › Display, and its tooltip spells the zone out.

| Function | Gives |
|---|---|
| `date(t, {year, weekday, month})` | "7 Nov", "Sat 7 Nov", "Tuesday 10 November" (`longDate`) |
| `time(t, {seconds})` | "14:02", "14:02:09" |
| `stamp(t, {seconds, zone})` | "7 Nov 14:02", with `zone` "7 Nov 14:02 UTC" |
| `when(t)` | "14:02" today, "Sat 14:02" this week, "7 Nov 14:02" before |
| `dayLabel(t)`, `dayKey(t)`, `dayDiff(t)` | "today"/"yesterday"/"Sat"/"7 Nov"; the day in the chosen zone; whole days between |
| `ago(t)` (also `util.ago`) | "3d ago" |
| `full(t)`, `span(a, b)`, `zoneName()`, `zoneLong()`, `zone()`, `setZone()`, `isUTC()` | tooltip form, a range, the zone's names, the setting |

A bare calendar date ("2026-11-04", a KEV due date) is never shifted by the zone, and a timestamp without a zone is read as UTC (the server stores UTC). ECharts axes follow the setting (`useUTC: T.isUTC()`). Network tables and labels take it through `ts()`, `tsShort()`, `day()` and `Z()` (the zone's short name) in `views/net/common.js`. Machine-facing text keeps ISO UTC on purpose: API parameters, `?range=` windows, file names, the copied diagnostics' "Generated" line, Copy summary (which says UTC), the SQL console's raw values and the notification webhook (server time).

## Time ranges

One control, `js/core/range.js` (`mount(el, {value, live, label, onChange})` returns `{get, set, hide, destroy}`), sits at the right of each view header: the Ops sub-bar, Network, News, the Intel directory and Cinema. Every copy has the same presets, look and keys:

* **Presets:** 24H · 7D · 30D · ALL. Ops and Cinema, which show live data, add 1H and 6H (`live: true`). A saved or linked value that is not a preset snaps to the next wider one (an old Network 6H becomes 24H).
* **Custom window:** brushing a chart (Network's overview timeline and Search logs histogram, Cinema's timeline) shows the window in the control as a chip, "3 Nov – 5 Nov ×" (in the app's one clock; a window under two days shows hours). Clicking the chip, or Enter/Space on it, goes back to the last preset; clicking a preset replaces the window. Cinema writes its brushed window into the URL like Network; a link to one picks the narrowest preset that holds it and brushes to it once the points are in. Cinema asks `/api/geo/points` with `spread=1`, so past its 40,000-point cap 30D and ALL sample evenly across their whole span (ALL is never shorter than 30D). The entity page's swimlane brush is separate. The Ops Activity panel's drag-to-zoom stays a magnifier inside that panel: the deck's panels take only a since-window from the API, so a custom window there would be ignored by every other panel.
* **Keys:** the control is one Tab stop (a radio group); ←/→ or ↑/↓ move and select, Home/End jump to the ends. The view reloads once the keys stop (250 ms).
* **Hidden, not dimmed,** where it does nothing: Network › Devices and Connect logs, Intel's Graph, Review and entity pages.

**Each view remembers its own range** (not one global value): Ops in `nd.range`, Network in `nd.network.range`, News in `nd.news` (a saved value that is not a preset, such as an old `1h`, falls back to 24H), Intel in `nd.entities`, Cinema in `nd.cinema.range`. The views answer different questions over different data: the deck and Cinema watch the last day of live feeds, Network looks back over logs that are often days old when imported, News reads a week, Intel's directory is all history by default. One global value would make a quick 1H look at the deck empty the Network view. Watch has no range: it shows what is new since you last looked (its marker).

**The URL carries it** as `?range=` (`24h`, `7d`, `30d`, `all`, `1h`/`6h` on Ops and Cinema, or `<from>~<to>` in ISO UTC for a brushed window): `#ops?range=7d`, `#network/hunt?range=30d`, `#news?range=24h` (the story list; a story's own URL has none), `#entities?range=7d` (the directory), `#cinema?kiosk&range=6h`. A link's range wins over the remembered one; a URL without one keeps the view's current range and has it written back. Changing the range replaces the current history entry (no new entry), so Back returns to the previous page with the range it had. The helpers `hashRange`, `withRange` and `syncHash` keep other parameters such as `?kiosk`.

Intel's range asks `/api/entities` for entities last seen in the window (`since_hours`); the per-type counts in the rail follow the window too, and reference entities that were never seen show only under ALL.

## Assessment

One component, `assessShell(d)` + `fillAssessment(root, d, {isCurrent, onArticle, drawer})` exported from `entity-panel.js`, renders the same block first in the drawer and at the top of the entity page (`#enp-assess`), so the "full profile" never says less than the drawer. CSS prefix `.drawer-`.

* **Verdict strip** (IP, prefix, domain, URL, hash): one plain answer first, built from `listed_by` (strongest active list by tier): "Listed as a botnet controller (QakBot) by Feodo Tracker since 4 Nov · seen on your network: no". Then the owner (`owner` on the entity: ASN, AS name, country, from the entity attributes or the offline DB-IP lite databases), each list with its trust tier in words (A primary authority, B established research group, C community list, corroborate first, D unverified report) and since when, then the counts (mentions, sources, claims). The mention-count KPI tiles and the trend chart are left out for indicators in the drawer. An indicator with no entity row (no feed or article names it) still gets the strip, from `/api/netlog/seen?context=true` (lists and owner), after a quiet `/api/entities/lookup`, so there is no 404. The entity page (`#entities/ip:…`, `domain:…`) does the same: the strip, the network answer, the lists and a line that nothing else is known, instead of a not-found page; the graph and the hover card look up first too. The sentence names the list by its short name ("by Feodo Tracker", not "by Feodo Tracker botnet C2"); the Lists rows keep the full name.
* **CVE patch facts:** CVSS, EPSS with its percentile, KEV added and due date, vendor and product with CISA's required action, advisory links (CISA CSAF advisories, the links in the KEV notes, NVD) and "on your network". The due date, action and notes come from the KEV catalogue record in the lake (`attrs.kev_due`, `kev_action`, `kev_vendor`, `kev_product`, `kev_links`, read by `osinthub/entities/api.py` from the record file under `raw/cisa_kev/`); without that file they are left out, never guessed. "What to do" names the deadline when known.
* **Seen on your network** for the entity's own value (IP, prefix, domain, hash, URL, CVE). The answer counts alerts as sightings, so it is never a false "no" when an alert exists; when the lookup fails it says "network check unavailable", not "no".
* **Why this matters now / What to do** from `/api/news/entity-brief/<id>` (below). For indicators "What to do" also says, from the lists and the network answer, whether to open the incident, search the logs for it, block it, corroborate first, or that nothing is needed.

Outside the drawer the block's chips open in the drawer (**Details**) and its copy buttons copy. The entity page's "Touches your network" card uses the same lookup for the entity and its indicators.

## Seen on your network

`GET /api/netlog/seen?v=<values,comma-separated>[&context=true]` (also `POST {values, context}`; `osinthub/netlog/seen.py`, mounted in `netlog/ext.py`) answers, for up to 500 IPs, CIDRs, domains, file or certificate hashes and CVEs per call (entity ids such as `ip:…`, defanged text and URLs are accepted): `seen`, `first`, `last`, `rows`, `log_types`, `devices` ([{id, name}], the home end of each row resolved to the device that held the address then), `n_devices`, `alerts` (incidents), `incident` (the most severe open one: new or acknowledged, not info, not dismissed or expected; `{id, severity, state, title, open}`), `demo` and `demo_also`, plus `logs` {rows, first, last}, `demo_loaded` and `ms`. IPs match either end of a connection and DNS answers; a CIDR matches every logged address inside it; a domain matches DNS queries, TLS server names and HTTP hosts equal to it or under it; hashes are read like the matcher reads them; CVEs come from Zeek notice, weird and software rows and IDS alerts. Demo rows are ignored unless the demo is loaded, then reported with `demo: true` (real data wins). Timings on the 938k-row test lake: one value 25-60 ms, 100 domains ~75 ms, 150 busy IPs 130-380 ms, 352 mixed values ~200 ms.

In the browser, `js/core/chips.js` holds the one client: `seenLookup(values)` (batched per tick, GET in URL-sized parts, cached a minute), `seenChip(item, {quiet, compact})`, `seenSlot(value)` + `fillSeen(root)` (placeholders filled in one lookup, left empty when never seen), `seenLine(item)` for verdict sentences and `huntFor(value, kind)`. The chip reads "Seen on your network · 2 devices · last Tue": amber when seen, red only with an open incident, a DEMO tag for demo-only sightings, and "Not seen on your network" (or "No network logs to check yet") only where `quiet` asks for it. Compact chips (tables, feed rows) switch to "Seen · 2 devices" on their own line below 640 px. A live `netlog_alerts` event (triage, rules, new matches, demo changes) clears the cache and refills the chips on screen. An `ip:port` value is looked up as the address, and a home address names its own device rather than the gateway it talked to. Clicking opens the incident (`#network/alerts/<incident id>`) or Network › Search logs filtered to the value over all data, and closes the drawer; inside clickable rows it never triggers the row. Used on news story cards in the list (the story's addresses, domains, CVEs and hashes from `top_entities`, one batched lookup per page; the card shows its strongest hit, an open incident first, compactly with the value it matched, and nothing when none was seen), news story and article IoC and CVE lists, Newly exploited and New CVEs rows, the event drawer (its IP and linked indicators, each CVE row), the entity drawer and the entity page.

Libraries: none beyond the shell's.

**Chips and hover cards (app-wide).** Any element with `data-entity="<type:value>"` gets a hover card after 380 ms on pointer devices (type, name, aliases, description, mentions, claims, sources, a mention trend, **Details** and **Open full page**); `data-nocard` opts out. Pressing anywhere outside the card cancels or hides it, and no card opens while the Network pivot menu or a deck menu is open, so the card never covers the menu it came from. Any element with `data-entity`, link or not, opens the drawer on click; Cmd/Ctrl/Shift- or middle-click opens its full page in a new tab ([opening things](#opening-things)). Any view can therefore make its chips follow the grammar by adding the attribute. Card CSS prefix `.ep-card`.

# Entities view

Below 1000 px the rail becomes chips (a sideways-scrolling row with edge fades while there is more that way), the page is one column and the graph panel docks at the bottom. The graph's bottom toolbar wraps instead of running off screen: below about 1240 px the time filter takes its own row, on a phone the origin toggles wrap too, and the canvas, legend and side panel follow the bar's measured height (`--gr-bar-h`); below 640 px rows, KPI tiles and the indicator table stack, and the map's line labels narrow. Libraries: Cytoscape for the graph only (vendored).

# Integration

Shared pieces that make the views one product. All are in `js/core/`, are wired once in `shell.js` `boot()`, and leave each view's own files alone apart from small hooks (listed below).

Grey: offline mode, the live connection is down, or every feed is off. It links to Settings › Sources. The same state paints the Ops sub-bar's **Source health ›** link.

## Reduced motion

With `prefers-reduced-motion: reduce`, one block at the end of `app.css` stops every CSS animation and transition: looping pulses (status dots, live chips), skeleton shimmers and spinners stop, slide-ins and the drawer finish at once (transitions run for 0.01 ms, so `transitionend` still fires), and the Cyber Cinema ticker no longer scrolls by itself but can be scrolled by hand. The top-bar tab fades are not animations (they follow scroll state) and the Explorer examples' fades are scroll-driven, so both keep working. The loader and the [guided tour](#guided-tour) also honour the setting. Motion driven from JavaScript checks `util.reducedMotion()` instead: the Cyber Cinema globe never auto-rotates (drag and zoom still work, and the autopilot still steps through events, cutting to each one instead of a 2.4 s camera flight), and the Ops Threat Origins globe and 3D map start without auto-rotation whatever was saved (the **Rotate** button can still turn it on).

## Guided tour

`core/tour.js`, loaded lazily and non-fatally from `main.js`. The light source is the brand mark's own emitter bar and the beam is its cone, so every step re-enacts the logo with the component as the desk. The bar lifts off the logo, takes a position outside the component being explained and shines on it, one component per step; the lit component pops slightly and the rest of the screen is grayed and darkened.

* **Starting it:** "Take the tour" in the "?" menu (or ⌘K "Take the tour of this page") tours the page you are on; the brand no longer starts it. The first visit runs a three-step task tour once (localStorage `nd.tour.done`), on Watch (at once, or the first time Watch opens): what Watch is for, where the network alerts are (the Network entry), and where to connect logs or try the demo, ending on Watch's setup checklist (or the link that shows it again). Step 2 lights the top-bar alerts badge when it is on screen and says so; without the badge it lights the Network entry with copy about Network. Step 3's "later" pointer names the **?** button where it shows and **More › Take the tour** on phones (≤760 px), where the ? button is hidden.
* **Content:** `INTRO` (the first-visit steps, also Watch's page tour) and `PAGES[view]` (per-page steps). `tab(v)` matches the top-bar or bottom-bar entry, whichever is on screen. A step is a selector (or `alt: [{sel, title, body}, …]`, alternatives tried in order, each with its own copy; `body` may be a function evaluated when the card shows), optionally narrowed by `has` (text match, `hasSel` to scope it), `tight` (light the union of the element's children rather than its box, for wide bars with a few small controls), `with` (also light a second element, such as a table's header row), `pad` and `pop: false`. Steps whose element is missing, hidden or off screen sideways (such as the News rail, which sits off-canvas behind its menu button on a phone) are skipped, so tours survive layout changes: Next/Back walk (iteratively) to the nearest step whose element is on screen, stay put if there is none further that way, and end the tour if the current step's element is gone too.
* **View changes:** a tour belongs to the view it started on. Any `hashchange` or `popstate` (Back/Forward, a `#view` link, a search result) ends it, and so does stepping or resizing after the active view changed some other way. "Take the tour" tours the new page.
* **Modal:** the card is `role="dialog"` `aria-modal`; while the tour runs every other child of `body` is made `inert` (only the nodes the tour changed are restored, so a closed drawer stays inert). Focus starts on the card, Tab and Shift+Tab cycle its visible buttons, and focus cannot reach the page. When the user ends it (Esc, Skip, Done) focus goes to the lit control if it takes focus, else the view's heading (made focusable for the moment); for Enter/Space it moves only after the key is released, so the key cannot also press what now has focus. A tour ended by navigation leaves focus to the router. On touch or ≤760 px its buttons are at least 44 px tall.
* **Keyboard:** while the tour is up it owns the keyboard (window, capture phase): Esc ends it, the arrows step. The `/` search shortcuts (global, News, Entities), News' `j`/`k`/Esc and the other single-key shortcuts are ignored until it ends.
* **Geometry:** the lamp shines square-on at one face of the component, and the beam is the trapezoid from the lamp's mouth to exactly that face's two corners, so it lands on the component's full edge by construction. Candidates sit centered off each face at a few short throws (above preferred, then the sides, then below); wide panels get the shortest, so their beam is a short even band, never a raking wedge or a floodlight. Each candidate is scored on light spilled outside the component (trapezoid area), a natural fan for compact components, standing in the top bar or the Ops sub-bar (items there are lit from the open space beneath them), and clutter. Clutter is sampled with `elementFromPoint` under the lamp, with the overlay hidden: text and controls count fully, canvases and charts partly, bare background not at all. Inside the component an even warm wash keeps content readable. A dark base under the beam makes the shaft darken what it crosses, so neighbours never look half-lit; a glowing line marks where it lands. An opaque pool of shadow under the lamp hides whatever it stands over. When there is no open ground around the component (it fills the screen, as the setup checklist does on a phone), the lamp, beam and pool fade out for that step and only the lit window and its outline show, so the lamp never sits on the text being explained. Highlights keep 8 px off the screen edges, and the pop never scales a component past its lit window (a component flush with the screen edge, such as the News rail, does not pop), so the frame never covers its text. Live components are re-measured when the lamp lands. The explanation card sits beside the component, on the side that hides least of the component, lamp and beam.
* **Scrolling:** targets are revealed by scrolling their own scroll container vertically, never sideways and never the page, so the top bar can't shift.
* **Motion:** steps tween lamp position, aim, scale, lit window and beam together (620 ms); Esc or Done flies the lamp back into the logo. Keys: ← →, Esc. `prefers-reduced-motion` cuts straight to each step.
* **Dimming:** one fixed layer with `backdrop-filter: grayscale() brightness()`, clipped by an even-odd `clip-path: path()` with a rounded window over the component.
* **Testing:** `window.__ndTour()` returns the current step's geometry and card box for browser tests.
* **Phones** (`isPhone()`): the first visit, and the tour of Watch, are the three-card phone tour (`PHONE_INTRO`): the answer card (`.watch-m-answer`, or the first card of the briefing until that exists), the Network tab ("Alerts live under Network; swipe right to acknowledge"), and the health pill with search and More. The cards are full width and sit above the bottom layer (or above the lit part when that is down there), with 44 px buttons; the page is inert and Tab stays in the card.

## Global search

One box in the top bar searches everything Night Desk keeps and opens what it finds; it navigates and never filters a view. `core/search.js` drives `#global-search`; the server side is `osinthub/search_all.py` behind `GET /api/search?q=&per=5[&groups=a,b]`.

* **Groups, in order of usefulness:** Network incidents (headline as in Network › Alerts, device, indicator, malware, evidence), Devices (the name you gave it, its own name, owner, type, note, every IP it has had, MAC in any spelling, hostname, maker), Stories, Articles, Entities (name, aliases, description; merged entities answer under the entity they joined, and an old id typed in full resolves too), CVEs and exploited flaws (KEV, CVSS, EPSS), Sources and settings (source name, provider such as "abuse.ch", and every Settings page and heading such as "Retention" or "Home prefixes", plus words people use for them such as "subnet"), Notes, and Feed items. The client adds app **Commands** from the ⌘K registry ([command palette](#command-palette)).
* **Ranking basics:** groups keep that order, except that a group whose best hit names the query exactly (an indicator, a device's IP, MAC or name, an entity's name or alias, a CVE id) moves ahead of groups without one. Within a group, incidents sort by how they matched, then open first, then severity and recency; a device matched by the query brings its incidents with it ("an IP finds the incident, the device and the entity"). Keyword hits must hold every word of a multi-word query, or the literal value of an IP, MAC, CVE, domain or hash; hits found by meaning are kept. A CVE shows once, in the CVE group.
* **Word starts and typos:** each word of four or more letters also searches its longer forms from the word list (names, aliases, titles, article words, settings and sources), so "log4j" finds "Apache Log4j2" and CVE-2021-44228; inside a group, hits whose name or title holds the query as whole words come first, then word starts, then text-only hits. A word of five or more letters that appears nowhere ("qakbto", "retenton", "ranswomware") also searches the most common known word one edit away (a letter changed, added, dropped or two swapped); those rows are marked as close matches, never exact, come after any exact ones, and the dropdown says "Showing close matches for …". Any MAC spelling is one value.
* **Why it matched:** every row carries `why = {field, text}` (for example *Malware QakBot*, *IP address 10.86.24.30*, *Also known as Qakbot*, *Setting Retention*), shown under the title with the query words marked. Highlighting matches the raw text and escapes each piece, so a term never lands inside an HTML entity.
* **Caps:** five rows per group with "N of M", then a **See all M …** row that loads that group alone (`groups=<id>&per=50`) in place, with an **All results** row to go back.
* **Keys:** `/` opens it for search, **⌘K / Ctrl+K** opens the same box with the matching commands at the top (every command before you type; ⌘K again closes). ↑ ↓ move across all groups, Home and End jump, Enter opens the highlighted row or the top hit (never "See all" or "Filter panels"), Esc closes. Enter typed faster than the 180 ms debounce runs that query first, never opening a hit of the previous one. Focus selects the last query so typing replaces it. The list is a popup of the input (`aria-activedescendant`), never a Tab stop: Tab closes it and moves on, and focus leaving the box any other way closes it too. Esc closes and returns focus to where it was before the box took it (⌘K, `/` or a click).
* **Opening a result** ([opening things](#opening-things), `core/open.js`): a click opens the Details side panel where there is one: an entity or CVE the shared entity panel, a feed item the event drawer. Rows that have a page carry a real link: an incident `#network/alerts/<id>`, a device `#network/devices/<id>` (the Devices tab selects it), a story or article its News pane, an entity or CVE its full page, a note the item it is on. Cmd/Ctrl/Shift-click or -Enter, or a middle click, opens that page in a new tab. A source or Settings heading opens its Settings section and scrolls to the card or heading, outlined for a moment; a command runs.
* **Modes:** the **KEYWORD** badge (amber) shows while the optional local AI helper is down and everything is ranked by keywords; **SEMANTIC** when articles, entities, CVEs and feed items were also ranked by meaning. Incidents, devices, stories, sources, settings and notes are always keyword matches. Everything works offline.
* **On Ops** the dropdown also offers an explicit **Filter panels by “…”** row (store `opsQ`); typing never filters by itself.
* Recent queries (six, in localStorage) show when the box is empty.
* **Speed:** the keyword indexes and the word list are built in the background at startup, one group at a time; a search sent meanwhile answers from the groups that are ready, marks the rest `warming` ("Still getting ready…") and the client asks again every 2 s until they answer. After a merge or new entities, the entity index is rebuilt in a background thread while searches keep using the last complete one. On the 900k-row test lake 20 mixed queries answer in about 13 ms p50 and 30–37 ms p95 server-side.
* **The route `#search?q=`:** on a phone it is a full-screen page: the search button opens it (one history entry) with the input focused, 48 px tall, with Clear and **Cancel**; recent searches, then the groups in 56 px rows, under a line such as "9 results · keyword match (offline)". Typing replaces `?q=` in the same entry (one Back leaves the search however much was typed); opening a result replaces the search entry with the result's page, so Back from it returns to where you were before searching; a feed item or command goes back to that page first and then opens or runs. Cancel and Esc are `page.back()` to it. On a computer the same route opens today's dropdown with the query in it, and the address returns to the page underneath when it closes. ⌘K does nothing while a phone sheet is open.
* **Adding a group** (server): `search_all.register_group(id, label, fn, order)` with `fn(q, ctx) -> (items, total)`; items carry `type`, `id`, `title`, `href` and `why`. The built-in Notes group reads the notes table when it exists; the notes package may replace it with one `register_group("note", …)` line. One failing group is reported as unavailable and never breaks the rest.

## Alerts badge

`core/alerts-badge.js` reads `GET /api/netlog/alerts/count` and shows the word **Alerts** and one number with its own word: "3 need you" (untriaged, not-expected, non-demo incidents of high or medium severity, [count rule](/data/netlog.md#the-needs-you-count)), "11 demo" when only demo incidents are open (dashed neutral border, never red), or "none need you". The label stays visible down to 900 px wide; the badge's text sits on the same line as the Sources pill's (`.al-sev` there is a plain flex row: the Alerts list's `.al-sev` rule no longer pushes it down). ## Entity chips

`core/chips.js` turns identifiers in rendered text into chips: `<a class="vx-chip" href="#entities/<id>" data-entity="<type:value>">`. They are real links (never spans, which views restyle, and never placed inside another link), so Cmd/Ctrl- and middle-click open the full page natively. The shared entity panel gives every chip its hover card and drawer; this module only adds the markup.

* **What it finds:**
  * IPv4 and IPv6 addresses, with CIDR as `prefix`. Dotted quads after "version", "release", "build" or "patch" are skipped. So are times and MAC addresses that look like IPv6.
  * CVE ids and `AS<n>` ASNs.
  * Defanged or plain domains with a known TLD. Infrastructure and reference domains such as ripe.net and github.com are skipped.
  * Actor, malware and tool names and aliases from `/api/entities?type=actor,malware,tool&limit=2000`, loaded once and matched case-insensitively on word boundaries. Common words are excluded, as are three-word names without a reference description (mostly people and companies) and plain capitalised words with fewer than three mentions unless they are on a short allowlist.
* **Ids:** they mirror `entities/normalize.py` `entity_id` (`cve:cve-…`, `asn:as…`, lower-case IPs and domains, slugged names).
* **API:**
  * `chip(type, value, label)` and `linkify(text)` build HTML.
  * `decorate(root)` wraps matches in text nodes, in place. Each changed text node becomes one `<ent-text class="vx-w">`, so flex and grid layouts keep their items.
  * `watch(root)` decorates now and again on every DOM change, batched in idle time.
* **Watched roots:** the Ops grid (so every feed and the World Map popups), Explorer, Cyber Cinema, Network and the event drawer. News and Entities already render their own chips.
* **Skipped:** inputs, links, buttons, `code` and `pre`, SVG, canvas, ECharts tooltips, `[data-entity]`, `[data-nochips]`, the entity panel and the search box.
* **Clicks:** a chip click is handled in the capture phase. It opens the entity panel (**Details**) and never the row it sits in, so a feed row still opens the event drawer everywhere else. A modified or middle click opens the full page in a new tab and never reaches the row either.
* **Network pivot values:** `.nv-v` values for IPs, prefixes, ASNs and domains get `data-entity` without being wrapped. They show the hover card, with a dotted underline, and the click stays the pivot menu. The menu gains **Details** and **Open full page**.

## Visual language

One design language across every view (v1.2), "warm lamplight in a dark room":

* **Type.** Page and section headings are serif (`--serif`, Fraunces, vendored with its 400, 500, 600 and 400 italic faces; add a face to `fonts.css` before using another weight): view titles, Settings › Sources and its "Every source" (an `h3` under the page's `h2`), News "All stories", story headlines, News card titles, Intel's directory heading ("Threats"), the entity page name and the entity panel name, Ops and SQL-console panel titles (sentence case, as Network's "Needs attention" card), Cinema's focus-card title. Story bodies read in the serif too (no Georgia). Data, ids, counts and small labels stay mono; running text is Inter.
* **Colour.** Text uses the warm tokens (`--text`, `--text-2`, `--muted`, `--faint`); the v1 cool greys (#8b93a1, #9aa1ab, #c9ced5, #d7dbe0, #eef0f3, #f1f3f5) and the v1 green-black on amber buttons are overridden (text on amber is `--on-accent`, the page's midnight). One accent: amber.
* **Red is a flag.** Red (and hues near it) appears only on flagged things: high severity, known-exploited (KEV) badges and bars, errors. Threat actors, CVEs, news actor chips, graph nodes and the entity eyebrow use the muted type hues; a global-search KEV hit keeps a small red KEV badge, not red row text. Entity-type colours live in one map, `util.TYPE_COLORS` (with `util.typeColor()`), which the Intel directory and graph (`entities/common.js TYPES`), chips (`core/chips.js`) and the entity panel (`core/entity-panel.js`) all import, so a type has the same colour everywhere.
* **Categorical palette.** One palette, `util.PAL`, of 11 warm, muted colours chosen by search under every rule at once: each pair at least 15 apart in CIEDE2000 (steps in hue and lightness); at least 12 from every v1 colour (no v1 cyan, blue, lavender, pink or mint under another name); blues, teals and cyans at most 45% HSL saturation; at least 4.5:1 as text on the panel, the lighter panel/hover card, a 12% chip tint of itself and the graph's label background, and at least 3:1 as a mark on the map; red only for known-exploited and severity. Eleven is the most those rules allow (a twelfth drops the minimum distance to 14), so:
  * **Event kinds** (`util.KINDS`) share nine non-red hues in pairs. The second kind of a pair has `mark: 'ring'` and is drawn as a ring on the map (markers, legend, quick toggles, layer menu), with a ring swatch in legends and tables, and hatched (bars) or dashed (lines) in the Ops Activity timeline and the SQL console: hue tells the family, the mark tells the member. `util.isRing`, `util.kindSwatch` and `util.kindDecal` carry this. The two biggest kinds on the map, BGP withdrawals and BGP origin changes, are different hues and both filled dots. Ring markers have no blurred halo, are at least 5 px across at world zoom with a stroke of 1.6 px or more, and the map logs any MapLibre style or layer error with `console.warn` (a bad paint expression once hid every marker). In MapLibre paint expressions a zoom `interpolate` must be the top-level expression, with any `case` inside its stops; a test checks this.

  * **Series** (`util.SERIES`, mirrored as `--vz-*` in CSS) are the same colours led by amber; Ops charts, BGP live, Top offenders, the SQL console's measures and the Campaign map draw from it. `tests/test_v12_visual.py` checks every rule.

## Updates

How a browser moves to a new version of the web client without a stale mix (B2-01, B2-02).

* **Caching.** Every web file is sent with `Cache-Control: no-cache`, so the browser checks its ETag on each load (a cheap 304 when unchanged). Responses of 1 KB and more are gzip-compressed when the browser asks (`GZipMiddleware` in `api.py`; app.css goes from about 560 KB to about 110 KB); the live stream (`/api/stream`, `text/event-stream`), images and fonts are sent as they are.
* **Build id.** At startup the server hashes every file under `web/` (relative path, size, mtime) into a 12-character id, `osinthub/api.py` `web_build_id`. `/api/health` reports it as `build`. It changes whenever any web file changes and stays the same across a plain restart.
* **One-shot clear.** Files cached by a server older than the `no-cache` header can stay "fresh" for hours, and the new page would then run with the old scripts (a blank page under "Ops", a dead phone bar). So the page document (`/`, `/index.html`) is answered differently whenever the request's build cookie is missing or names another build:
  * The cookie is `nd_build_<port>` (`nd_build` when the address has no port), set as `<name>=<id>; Path=/; Max-Age=31536000; SameSite=Strict` (no `Secure`: the app may be plain http). It is per port, because cookies are per host: two Night Desk servers on one machine would otherwise keep overwriting each other's cookie and clearing each other's cache.
  * That response is always a full 200 (never a 304) with `Cache-Control: no-store`, so no browser keeps it and its headers never come back on a later revalidation.
  * On a secure context (`https://`, including behind a TLS proxy, and `http://127.0.0.1` or `http://localhost`) it also carries `Clear-Site-Data: "cache"`, `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`. In the lab, Chrome emptied its HTTP cache on the clear but kept the replaced page's scripts in the tab's renderer memory cache and served them to the new page, so the reload stayed broken. A cross-origin-isolated document must open in a fresh renderer process, which loads every file anew. The app embeds nothing from other origins.
  * On a plain-http LAN address (`http://192.0.2.10:8787`) the browser would ignore all three and log an error for each, so they are not sent. There the stale-code check below is the recovery.
  * With a matching cookie the document is served normally (`no-cache`, ETag, 304). No script, stylesheet, vendor file, API or stream response ever carries any of this.
* **Stale-code check** (an inline script in `index.html`, the one file that is always current; the only inline script, allowed by the server's [Content-Security-Policy](/architecture/deployment.md#content-security-policy) through its hash; every other script is a file and no markup uses inline `on…=` handlers): a current `main.js` sets `window.ndMain = 1` before anything else. If it is missing once the page has loaded (an older `main.js` the browser kept, or none arrived), the page is covered by "Night Desk didn't load. Part of the app is an older copy your browser kept." with **Clear cached files and reload**. That button (`window.ndClearAndReload`, styled inline because `app.css` may be old too) re-fetches every same-origin file the page loaded, plus `main.js`, `core/shell.js` and `app.css`, with `cache: 'reload'`, expires the build cookie and reloads. It works on any origin: in the lab, a plain-http LAN tab with v1.1 files cached showed it on the first normal reload, and one click gave a working v1.2 in the same tab. Only a `main.js` from before v1.2 is caught this way; later versions keep the marker, and their own `fatal()` (next item) covers a failed start.
* **When the app fails to start** (`main.js` `fatal()`): **Clear cached files and reload** re-fetches every same-origin file the page has loaded with `cache: 'reload'`, expires the build cookie (so the next `/` carries the one-shot clear) and reloads; it uses `index.html`'s `window.ndClearAndReload` when present. **Reload** just reloads.
* **Sign in again** (`core/api.js`): when the server asks for a password (`OSINTHUB_PASSWORD`) and an API call gets **401** (the browser's sign-in has gone or was refused), one banner at the top says "Sign in again: reload the page." with a **Reload** button; the call still fails normally, so each view shows its own error state ([who can reach it](/architecture/deployment.md#who-can-reach-it)).
* **A tab left open across an upgrade** (`core/update.js`, imported non-fatally after boot): it remembers the build the page was served as (the build cookie at load, else the first `/api/health`). It asks `/api/health` again every 5 minutes, when the tab becomes visible, when the live stream reconnects (`live.on('status')`), and every 4 s while the stream is down. When the build differs it shows a one-line bar, "Night Desk was updated · Reload" (`role=status`; Reload reloads; × dismisses it for that build). Tests: `tests/test_v12_upgrade.py`.

## Small hooks in view files

* `views/network.js`: **Details** and **Open full page** in the pivot menu, and `#network/<tab>` deep links on load and on hash change.
* `views/news.js`: opens `#news/story|article/<id>` on a hash change after boot, and reads the current hash at boot.
* `panels/world-map.js`: vendored glyphs and the **Offline (local)** basemap. That basemap is the default (online basemaps are opt-in) and is forced when `api.health()` reports `offline`. The map is created only after the flag is known. An online basemap that fails to load (style error, 4 tile errors, or no style after 8 s) falls back to it.
* `panels/feeds.js`: Bluesky profile lookups (names, avatars from `public.api.bsky.app`) are opt-in: none until the user clicks an avatar in Social OSINT (stored as localStorage `nd.bsky.profiles = '1'`), and never in offline mode.
* `views/entities/graph.js`: cytoscape from `web/vendor/` only (no CDN fallback).
* `core/api.js`: `api.health()`, a cached `/api/health` (`{ok, sources, offline, build}`). If it cannot be read, the client treats the server as offline.
* `views/cinema.js`: vendored globe textures.
