# Conventions

All endpoints are under `/api/` (behind Caddy too, which serves the app at the site root). List parameters are comma-separated. `since_hours` limits results to the last N hours (also `hours` on `/api/stats/timeline` and `minutes` on `/api/metrics`): fractions count (`0.5` is the last 30 minutes, `1.5` the last 90), `0` is an empty window, and leaving it out means all history. `q` is a case-insensitive contains-text match on title or summary, or an exact IP, ASN or tag; `%`, `_` and `\` in `q` are literal characters, not wildcards (the same on `/api/news/stories` `q` and `/api/entities` `q`, and for watchlist keywords). Counts such as `k` (search results, at least 1) and `similar` (0 for none) are validated, so a negative value is a 422 rather than counting from the end. An unknown `order` (`/api/events`, `/api/news/stories`) or `sort` (`/api/entities`) is a 400 naming the allowed values, not the default ordering.

Validation: a negative or oversized `limit`, `offset`, `evidence`, `k` or `similar` is a 422 (FastAPI validation, with the field named in `detail`); each `limit` has the maximum given below, and `offset` is at most 2^63 − 1. A time window (`since_hours`, `hours`, `minutes`) that is negative, NaN or infinite is a 400; one longer than about 200 years (1,752,000 hours) means all history. News times (`since`, `until`, `new_since`) that do not parse, or a relative time reaching before year 1 (`100000000d`), are a 400 `bad time`. No parameter value should produce a 500.

Every request must carry a `Host` the server allows (loopback names, plus `OSINTHUB_ALLOWED_HOSTS`), or it gets **421**; a write whose `Origin`/`Referer` is another site gets **403** ([Host allowlist](/architecture/deployment.md#host-allowlist-dns-rebinding)). When `OSINTHUB_PASSWORD` is set, every request (pages, files, the live stream) also needs `Authorization: Basic` with that password and any user name, else **401** with `WWW-Authenticate: Basic realm="Night Desk"`; only `GET /api/health` from this machine is exempt, and ten different wrong passwords from one address in 10 minutes give **429** for 15 minutes (IPv6 also: 50 from one /64) ([who can reach it](/architecture/deployment.md#who-can-reach-it)). The order is Host, then password, then the CSRF check. A request body over its cap is **413**, counted while it streams in: 16 MB, except `/api/upload` (65 MB: its 64 MB file cap plus the multipart envelope) and `/api/netlog/import` (2 GB per request, [import](/data/netlog.md#import)). A bind beyond loopback without a password refuses to start (`python -m osinthub` and also when the app is imported, e.g. `uvicorn osinthub.api:app`); a bind given only on the uvicorn command line is caught per request: without a password, a request that arrives on a non-loopback address of the machine gets **503**. Every response carries the [Content-Security-Policy](/architecture/deployment.md#content-security-policy). FastAPI's `/docs`, `/redoc` and `/openapi.json` are 404 unless `OSINTHUB_DEBUG=1`; this page is the API reference.

Paging: every list that takes `limit` and `offset` (`/api/events`, `/api/entities`, `/api/news/stories`, `/api/news/articles`) sorts with the row id as a final tiebreaker, so consecutive pages are disjoint and together return every row exactly once (while the data does not change between requests).

## Counting addresses

Several feeds list the same bad address (Feodo Tracker and ThreatFox, Spamhaus and others), so every count the dashboard shows (the world map and Cinema points, Threat Origins, Top Offenders, the Activity timeline and the kind totals) counts each address once. Of the selected events sharing an IP, one stands for it (its main listing): an original listing before a re-listing feed's copy (ThreatFox, URLhaus and SSLBL, which repeat Feodo C2s and each other), then the most severe, then the newest. Events without an IP count one each. The address counts under the kind of its main listing, so without a kind filter an address that two kinds list adds to one kind only, and a re-listing kind (`malware_ioc`, `malware_url`) shows fewer than its own rows; with a kind filter every address of that kind counts. `/api/events` and the SQL console still list every event. The panels say this in one sentence (`util.COUNT_RULE`, on the timeline total, Top Offenders' column head and the SQL console's kind list), and their totals read "N addresses", "N events" or "N addresses + M events" from the `a` count (`timeline` and `top` rows carry `a`, how many of `n` are addresses).

Each endpoint's filters apply before the count, and each takes only its own: `/api/stats/timeline` takes the window (`hours`), `kinds`, `categories` and `q`; `/api/geo/points` the window, `kinds`, `sources` and `q` (and keeps located events only); `/api/stats/countries` the window, `kinds` and `categories` (events with a country only); `/api/stats/top` the window and `kinds`; `/api/stats/summary` the window only. So their totals agree for the same window and kinds, and an endpoint without `q` or `categories` ignores them (with a panel search active the timeline and the map dots narrow to it; Threat Origins, the map shading and Top Offenders do not). Because the map keeps located events and the country counts keep events with a country before choosing the main listing, an address whose feeds disagree on location can sit in a different country there than on the map; each still counts it once.

It is one grouped `arg_max` per address in DuckDB (`_one_per_ip` in `osinthub/api.py`). On a synthetic 5,000,000-event lake (about 1.27 M addresses) on a shared machine, the timeline takes about 0.02 s for 24 h and 0.08 to 0.12 s for 90 days (v1.2: 0.03 s), the summary about 0.1 to 0.25 s, and Top Offenders' IP tab about 0.02 s for 24 h and 0.1 to 0.2 s for all history.

How many feeds listed an address is shown beside it rather than adding to the count: `feeds` and `sources` on `/api/stats/top?field=ip`, `/api/stats/feeds`, and `reported_by` on `/api/events/{id}`. It is corroboration, not a confidence score: some feeds copy each other (ThreatFox and URLhaus repeat Feodo Tracker's C2s, [ThreatFox](/sources/current/threatfox.md)), so N feeds is not always N independent reports, and the UI says so. These counts are for the local UI only: they never go into an AI prompt, an embedding or an export (abuse.ch terms).

| POST | `/api/sql` | JSON `{sql}` | <a id="sql-console"></a>**Off unless the server was started with `OSINTHUB_SQL_CONSOLE=1`** (or `OSINTHUB_DEBUG=1`; `config.SQL_CONSOLE`): while off every call gets **403** `{"detail": "The SQL console is off. Start Night Desk with OSINTHUB_SQL_CONSOLE=1 to turn it on."}`, and `/api/health` / `/api/settings/about` say `sql_console: false`. No app feature uses it (the Ops panels' KEV marks and ASN names have their own GETs below), so off loses nothing but the console. When on: `{columns, rows}`. Read-only: one SELECT/WITH/PIVOT/UNPIVOT/DESCRIBE/SUMMARIZE/SHOW statement (checked with DuckDB's own parser and tokenizer, so words such as `update` or a `;` inside a string literal, a quoted name or a comment are fine), capped at 5000 rows and 8 seconds. PIVOT and UNPIVOT work when DuckDB parses them as one SELECT, on their own or inside a CTE, subquery or join: DuckDB's short form with its values listed (`PIVOT events ON kind IN ('kev', 'c2') USING count(*) GROUP BY source`), the SQL-standard form (`SELECT * FROM events PIVOT (count(*) FOR kind IN ('kev', 'c2'))`) and UNPIVOT in both forms. A short-form PIVOT without an IN list (or with `IN (SELECT ...)`) is refused with a hint to list the values (`SELECT DISTINCT kind FROM events` shows them): DuckDB runs it as several statements, and the parser check cannot see what the hidden first one reads. The rule (`_sql_check` in `osinthub/api.py`): the text that runs is exactly the text whose parse was checked, never a rewritten copy. Tables are an allowlist: every table a query names (in FROM, JOIN, PIVOT/UNPIVOT, TABLE, DESCRIBE, SUMMARIZE or SHOW, with any catalog and schema parts) must be a CTE of the same query or an existing table or view of the app's database (a WITH name must be a plain word that no table, view or system object already uses, because DuckDB scopes a CTE to its own subquery and a reused name would let the real table through elsewhere in the text) (`duckdb_tables()` / `duckdb_views()`, which include `information_schema`), and table functions are limited to compute-only and catalog ones, so a file path or URL in any spelling (`'x.csv'`, `"dir/x".csv`, globs, `s3://`, `http://`) is refused before anything runs. Behind that, the app's DuckDB never installs or auto-loads an extension (json, parquet and icu are built in; `db.DUCKDB_CONFIG` for every DuckDB the app opens) and may touch files only in the lake and its database folder (`allowed_directories`, `enable_external_access = false`, through `db.restrict`). The app's two other DuckDB connections are shut tighter: the DuckDB vector index (`vectors.duckdb`) reads no file at all besides its own database, and an upload's CSV reader only that one upload (`allowed_paths`; it spills into its own folder under the lake's `tmp/duckdb-upload`); neither can switch it back on, and both have every setting locked (`lock_configuration`), extension auto-load included (`tests/security/test_v12_pf_sql.py` checks each connection). Nothing the console returns names a server path (v1.2 sqlgate): functions and views that show settings, database files or the environment are refused wherever they appear, in any spelling (`api.SQL_FUNCS_BLOCKED`: `current_setting`, `getenv`, `which_secret`, `write_log`, `duckdb_settings`, `duckdb_databases`, `duckdb_extensions`, `duckdb_secrets`, `duckdb_temporary_files`, `duckdb_logs` and the rest DuckDB 2.0 lists in `duckdb_functions()`), with "… shows server settings or file locations, so the SQL console doesn't allow it"; of DuckDB's system views only the catalog ones that list tables, columns and types are readable (`api.SQL_SYSTEM_VIEWS_OK`; `pg_settings`, `duckdb_databases`, `pragma_database_list`, `duckdb_logs` and `pg_prepared_statements` are not), and DuckDB's own folders (`home_directory`, `secret_directory`, `extension_directory`) are `<db folder>/.duckdb/...` with `allow_persistent_secrets = false`, so they never name the home folder. The app's own tables do store paths (`netlog_files.path`, `events.raw_path`, `runs.raw_path`, the watched-inbox setting): the data stays as it is and every console answer is rewritten on the way out instead (`_sql_redactor`): in every string cell, nested LIST/STRUCT/MAP values and JSON text, every column name and every error message, only the home folder is treated as private: the home folder (`$HOME` and the account's) becomes `~`, and the database folder `<db>`, the lake `<lake>` and the app's own folder `<app>` when they sit inside it (a Mac owner's `~/Projects/nd/lake`), longest first, as given and resolved, with either slash, only as a whole path (not inside a longer name such as a URL path). Paths outside the home folder are never rewritten (`/data/db` or `/app` in the Docker image, an external drive): they say nothing about the owner, and the same text is ordinary data in logs and articles (`/app/login.php`, MongoDB's `/data/db`). A one-part home such as `/root` is not treated as private. So `SELECT path FROM netlog_files` reads `<lake>/raw/netlog/...` and SUMMARIZE's min/max the same. The rewrite only catches a path written out whole: almost any string function (`upper`, `substring`, `hex`, `'x' || path`, `split`, `reverse`) returns it in a form the rewrite does not recognise, so it hides paths from ordinary answers and screenshots, not from someone who sets out to read them. That is acceptable because the console is off unless the owner turns it on, and the owner can already see these paths in Settings › About, `/api/lake` and the network-log views. The `settings` table is not readable at all (`api.SQL_PRIVATE_TABLES`): it holds the notification webhook address with its token and the log senders' token hashes, which the rest of the app masks, so any query naming it gets "The settings table holds the app's own settings, some of them secret …"; `pragma_storage_info` is not allowed either (its min/max statistics show any table's values). No other table holds a secret (audit, v1.2 sqlgate: the Radar token is a file in the db folder, API keys come from the environment, device tokens are sha256 hashes in `settings`). Refusals and errors never repeat a path: a file path gets "Reading files or URLs through the SQL console is not allowed", an unknown plain name "There is no table or view named X", and a DuckDB error only "Query failed — check your SQL." (the detail goes to the server log). A query DuckDB parses as one SELECT but the check cannot read is refused with a plain message; a syntax error gets "Could not parse the query." Every DuckDB type comes back as plain JSON: integers as numbers, except that an integer outside JavaScript's safe range (beyond ±(2^53 − 1), e.g. a large BIGINT, HUGEINT or UBIGINT) is an exact decimal string such as `"18446744073709551615"`; DATE/TIME/TIMESTAMP as ISO strings (an infinite DATE or TIMESTAMP value as `"infinity"`/`"-infinity"`, as a column and at any depth inside a LIST, ARRAY, STRUCT, MAP or UNION value: DuckDB's client would hand back 9999-12-31 / 0001-01-01, so a flag column shaped like the value says which leaves were infinite, `_sql_inf_mask`, and a MAP is rebuilt from its entries so an infinite key never folds into a real 9999-12-31 key; a real 9999-12-31 stays a date), DECIMAL as a number (a string when a float would lose digits), INTERVAL as text such as `1 day, 0:00:00` (months count as 30 days), UUID as text, BLOB as DuckDB's escaped text (`\xAA`), NaN/±Inf as `"NaN"`/`"Infinity"`/`"-Infinity"`, LIST/STRUCT/MAP element by element. |

| GET | `/api/routing/watches` | | `{cards: [{id, kind, label, state: "normal"\|"changed"\|"unchecked"\|"pending", sentence, last_checked, checks: [{source, name, state: "ok"\|"failed"\|"stale"\|"pending", at, why}], needs_you, open, events: [{kind, level: "needs_you"\|"info", source, title, short, summary, opened, seen, cleared}]}], paused}` |

The four routing sources (`rpki_roas`, `cf_radar_bgp`, `ripestat`, `ris_live`) are ordinary sources for
`/api/sources`, `/enable` and `/run`; while the watchlist is empty their `unavailable` says so and `needs` is
`"watchlist"` (`"key"` for Radar without a token). A routing source can also report `status: "paused"` (daily data limit).

# News

All under `/api/news` ([news data](/data/news.md)). Times accept ISO 8601 or a relative `24h` / `7d`.

|---|---|---|---|
